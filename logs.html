Log 2000-12-15

Programmer's Log

James

  • Worked on multi-player code.
  • Helped everyone else with their projects.
  • Upgraded the file server to Windows 2000 Server.
  • Upgraded Source Off Site to 3.01.
  • Working on enabling remote access / virtual private networking (VPN).

Steve

  • Fixed bug in SentinonAI that causes Sentinon to deploy when player is within range but not visible (i.e., Sentinon apparently could see through walls but not fire through them ... now Sentinon can't see through walls either). Side effect of this fix is that Sentinon will be collideable when idle, but I really don't think this is a significant thing. If it is, someone let me know.
  • Removed all the conditional compilation stuff for NO_SET_FACING_ANGLE. Once checked in, this will have a wide impact so I am going to be working to minimize that impact by getting into a lot of StarTrek code that uses SetFacingAngle(), replacing those obsolete calls with appropriate new calls.
  • Added CEntityAnimatedUpperBody to handle upper body stuff, as opposed to using CEntityAnimated for upper bodies.
  • Modified Crater model to use CEntityAnimatedUpperBody. More work needs to be done to restore all previous functionality. Expect some anomalies with this change, please report any errant behavior to Steve.
  • Added property to move behavior which allows for specification of alternate sequence, such as Targ using a charge animation.

Loren

  • Got Zax "Drop" button to work... many changes resulted from this... I still need to get dropped items to fall in predictable places and not paint you into a corner.
  • Added ability to set a powerup to respawn in one of three modes.
  • Made *ALL* collidable polygons flash if wrapped backwards or self-crossing... there is no option to disable this, because it is always considered a bad thing... Things like the ship and targ dens need a big concaved polygon to work right.
  • Starting to look into net-game stuff...
  • Worked primarily on SDL port:
  • non-trivial Unix file-parsing code... (added case insensitivity, symbolic-link infinite cycle traversal, dot-file support, etc.)
  • Broke out 2-d and 3-d audio seperately:
  • 2-d audio will be handled by SDL_mixer which I put togeather a skeleton binding for.
  • 3-d audio will be handled by OpenAL, and is currently turned off on non-windows builds
  • preliminarly added Tcl/Tk support for dialogs (SDL has no provisions for multiple windows), Tcl/Tk [aka "wish"] is a seperate executable so it need no special linking considerations... This probably confines us to targets with windowing systems... I'd like to address this later.
  • finished a preliminary implementation of the event loop... including massive keyboard changes... reformatted keyboard lookup table on both SDL and win32 targets.
  • it looks like it's now getting as far as trying to draw to the screen...
  • added some direct-play stubs to get john's new lobby code compiling.
  • Still trying to get my head around networking...
  • dealt with some "falling" code, includeing grenades in STAT...

Log 2000-12-08

Programmer's Log

James

  • Mostly helped everyone else with their respective tasks.
  • Has a design meeting to figure out several nagging issues in the Zax design.
  • Working on multiplayer mode.
  • Fixed disabled hot keys in JWindows.
  • Made materials generator enforce limits for number of items.
  • New "generator" cheat code for testing.
  • Weapons show ammo count in inventory.
  • Trying to get companion drones working.

Steve

  • Continuing to clean up and retro-document AI code.
  • Eliminated SetFacingAngle() function, wrapping change in conditional compilation structure (to avoid breaking too much stuff until I get the rest worked out).
  • Added separate functions to CEntityAnimated for specifying and retrieving movement angle and aiming angle.
  • Inserted class between CEntityBehaviorTurnToAngleBase and both CEntityBehaviorTurnToAngle and CEntityBehaviorTurnToTarget(CEntityBehaviorTurnMovingAngle and CEntityBehaviorTurnAimingAngle, respectively) to ensure that new functions for specifying and retrieving movement and aiming angle are used.
  • Began adding code to A.I.'s to allow bad guys to aim and shoot in different directions.

Loren

  • Worked on finishing up SaveGame GUI issues... Some minor things remain issues, but it is now functionally complete.
  • Got a new PropertyEditor on arrays to support out-of-order insertion/removal of items.
  • Finished up remaining major issues with Zax's SaveGame Gui.
  • Implemented a new editing system for arrays so users can do out of order inserts and deletes in PropertyArrayPropertys and ObjectArrayPropertys.
  • Ported ShakeScreen Action from STAT to Zax. *)
  • Got Zax to compile under linux ...again.
  • I added a backwards compatible array count to ObjectArrayPropertys... this should fix some things in save-games (I hope)
  • I added a PlasmaTile Generator to the TilePallette for Chris et al.
  • I made ConfigControl (Which does the keyboard remapping) support an arbitray number of "Actions".
  • Implemented "Drop" in Zax... (Unfortunately this requires loading all Item models at startup...)
  • Fixed Zax's ship's model's polygon to no longer be inside out... this was required so you could drop things inside the ship. (otherwise they landed outside the ship.
